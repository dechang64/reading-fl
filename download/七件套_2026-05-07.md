## 一、公众号 | SOHOForce OPC AI开放创造实验室

### 标题
**英伟达中国份额归零：算力自主之后，数据怎么办？**

### 发布时间
**2026-05-07 20:00**（公众号晚间深度阅读高峰 19:30-21:00）

### 正文

黄仁勋在最近一次采访中承认了一个事实：英伟达在中国AI芯片市场的份额已经降至0%。

出口管制层层加码，直接面向中国客户的销售完全停滞。华为昇腾、寒武纪等国产替代趁势崛起，算力芯片概念股在5月6日集体走强。

这条新闻的解读角度很多。有人看到"国产替代的机会"，有人看到"AI研发成本上升"，有人看到"中美科技脱钩加速"。

但作为做联邦学习研究的人，我看到的是另一个问题：**算力墙之后，还有一堵数据墙。**

---

### 两堵墙

第一堵墙是算力墙。

英伟达断供之后，国内AI项目的算力来源只能转向国产芯片。华为昇腾910B、寒武纪思元370、海光DCU——这些芯片的单卡算力与H100/A100仍有差距，但差距在缩小。DeepSeek V4在国产算力上取得突破，说明算法优化可以在一定程度上弥补硬件差距。

算力墙很高，但有梯子。

第二堵墙是数据墙。

这堵墙更隐蔽，也更难翻。

《数据安全法》《个人信息保护法》已经实施多年，数据出境的安全评估越来越严格。医疗数据不能出境，金融数据不能出境，教育数据不能出境。甚至不同机构之间的数据共享，都需要经过复杂的合规审批。

这意味着什么？

意味着即使你解决了算力问题——用国产芯片替代了英伟达——你仍然面临一个根本性的架构选择：**数据集中训练，还是分布式协作？**

---

### 传统模式的困境

传统AI训练的模式是"数据集中，模型分发"。

把所有数据搬到一台（或一组）服务器上，用大算力集中训练，然后把训练好的模型部署到各个终端。

这个模式在算力充足、数据自由的条件下效率最高。但当两个前提同时被打破——算力受限、数据不能集中——它就变成了最差的选项。

具体来说：

**算力受限时，集中训练成本暴增。** 国产芯片算力密度低于英伟达，同样的训练任务需要更多的卡、更长的时间、更高的能耗。如果所有数据都集中到一处训练，算力瓶颈会被放大。

**数据不能集中时，合规成本暴增。** 跨机构数据共享需要安全评估、隐私计算、审计追踪。这些"非功能性需求"在工程上往往比模型训练本身更复杂。

两堵墙叠加，传统模式几乎走不通。

---

### 联邦学习的"意外战略价值"

联邦学习被发明的时候，解决的是隐私问题——让数据留在本地，只共享模型参数。

但当算力墙和数据墙同时出现，联邦学习获得了一个"意外"的战略价值：**它天然适配算力分散、数据分散的现实。**

为什么？

**第一，分布式训练降低单点算力压力。** 联邦学习中，每个客户端在本地用自己的算力训练，服务器只负责聚合参数更新。这意味着训练算力被分散到了各个客户端，不需要一台超级计算机。

**第二，数据不出域天然满足合规要求。** 原始数据永远不离开客户端，从架构层面规避了数据出境和数据共享的合规风险。

**第三，国产芯片+联邦学习=自主可控闭环。** 客户端用国产芯片做本地训练，服务器用国产芯片做聚合。整个流程不依赖任何外国硬件和外国云服务。

这不是理论推演。我们实验室的Reading-FL项目已经验证了这条路径——三个校区，273条书摘，数据全部留在各校区本地，用FedAvg聚合，准确率85.5%。

---

### 从战略到个人：OPC的算力民主化

上面说的是宏观层面。落到个人层面，有一个更值得关注的变化。

当算力不再是少数大公司的特权——国产芯片价格下降、云算力按需计费、AI模型开源——个人创作者获得算力的门槛正在快速降低。

OPC（Open Platform Creator）的核心前提就是：**一个人+AI工具链=一个团队。**

但这个前提成立的关键不是"AI工具够不够好"，而是"算力够不够便宜"。

英伟达断供短期内会推高算力成本，但中长期会加速国产替代和算力民主化。就像当年CPU被Intel垄断，AMD崛起后价格才降下来一样。

联邦学习在这个过程中的角色是：让算力民主化不会以牺牲数据隐私为代价。

**你可以用便宜的算力训练自己的模型，你的数据不需要交给任何人。**

---

### 一个提醒

最后说一个可能被忽视的风险。

英伟达断供之后，"国产替代"会成为高频词。但替代不是简单的"换芯片"——软件生态、开发工具、性能调优、兼容性测试，这些隐性成本往往比芯片本身更高。

如果你正在做AI项目，我的建议是：

1. **不要等断供了才考虑替代方案。** 现在就开始在国产芯片上测试你的模型。
2. **不要把所有数据集中到一个地方。** 联邦学习不是可选项，是必选项。
3. **不要低估合规成本。** 数据安全法不是纸老虎，处罚案例已经越来越多。

英伟达走了。但留下的问题，比芯片本身更值得思考。

## 三、知乎 | 小蠹OPC

### 标题
**英伟达断供后，联邦学习为什么成了必选项？**

### 发布时间
**2026-05-07 21:00**（知乎晚间技术阅读高峰 20:00-22:00）

### 正文

黄仁勋承认英伟达中国AI芯片份额降至0%。这条新闻的讨论焦点几乎都在"国产替代"上——华为昇腾能不能替代H100？寒武纪的算力密度够不够？训练成本会涨多少？

这些讨论都有价值，但忽略了一个更深层的问题：**当算力受限且数据不能出境时，AI训练的架构应该怎么设计？**

传统答案是"集中训练"——把所有数据搬到超级计算机上。但这个答案在当前约束下几乎不可行。

我想从三个层面分析，为什么联邦学习从"可选项"变成了"必选项"。

---

### 一、算力层：分布式训练是唯一可行路径

国产AI芯片的单卡算力与英伟达旗舰产品仍有差距。这不是秘密。

但更关键的问题是：**即使单卡算力追平了，集中训练的算力需求也在指数级增长。** GPT-4的训练用了约25000张A100，训练成本超过1亿美元。下一代模型的训练算力需求可能再翻10倍。

没有任何一家中国公司能独自承担这样的算力投入——即使芯片是国产的。

联邦学习的分布式架构提供了一种解法：把训练算力分散到各个客户端。1000个客户端，每个用1张国产芯片，等效于1台1000卡的服务器。但成本由1000个参与方分担，而且不需要建设集中式数据中心。

这不是理论。Google的Federated Learning已经在数亿Android设备上运行了多年。Meta也在用联邦学习训练键盘输入预测模型。

**算力分散的现实，天然适配联邦学习的架构。**

---

### 二、数据层：数据不出境是硬约束

《数据安全法》第31条规定，关键信息基础设施运营者在中国境内收集和产生的个人信息和重要数据应当在境内存储。《个人信息保护法》第38条对个人信息出境提出了严格的条件要求。

这些法律不是"建议"，是"硬约束"。违反的处罚包括警告、罚款、暂停业务、吊销执照。

对AI训练来说，这意味着：

- 医疗AI：患者数据不能离开医院
- 金融AI：交易数据不能离开机构
- 教育AI：学生数据不能跨校区共享
- 企业AI：商业数据不能离开企业内网

传统集中训练要求把所有数据搬到一处，直接违反上述约束。

联邦学习的核心设计——**原始数据永远不离开客户端，只传输模型参数更新**——从架构层面解决了这个问题。

---

### 三、合规层：联邦学习降低合规成本

即使技术上能做到安全的数据传输（比如用加密通道），合规成本也不容忽视。

一次数据出境安全评估的周期通常为45-60个工作日。跨机构数据共享需要签署数据处理协议、进行隐私影响评估、建立审计机制。这些"非功能性需求"在工程上往往比模型训练本身更耗时。

联邦学习通过"数据不出域"的设计，直接规避了大部分合规流程：

- 不需要数据出境安全评估（数据没出境）
- 不需要跨机构数据共享协议（数据没共享）
- 审计对象从"原始数据"变成"模型参数"（参数不包含个人信息）

**合规成本从"项目级"降低到"参数级"。**

---

### 联邦学习的"意外优势"

上面三点说明，联邦学习在当前环境下具有战略价值。但还有一个经常被忽视的优势：

**联邦学习天然适配国产算力生态。**

原因很简单：联邦学习的客户端训练是轻量级的。每个客户端只需要在本地数据上做几个epoch的微调，不需要从头训练大模型。这意味着对单卡算力的要求远低于集中训练。

华为昇腾910B的单卡算力虽然不如H100，但做联邦学习的本地微调完全够用。寒武纪思元370也是同理。

**集中训练需要超级计算机，联邦学习只需要"够用的计算机"。**

这对国产芯片生态是一个利好：不需要等国产芯片追平英伟达，现在就可以开始部署联邦学习。

---

### 三个尚未解决的问题

说了这么多优势，也要坦诚面对问题。

**问题一：通信效率。** 联邦学习需要频繁传输模型参数更新。大模型的参数量动辄数百亿，即使压缩后每次通信也有几十MB到几百MB。在弱网环境（比如偏远地区的医院）下，通信延迟可能成为瓶颈。

目前的解决方案包括梯度压缩、Top-K稀疏化、量化传输等，但都有精度损失。我们实验室在Embodied-FL项目中用Top-K稀疏化实现了10倍通信压缩，精度损失可忽略。但这是在特定场景下的结果，通用性有待验证。

**问题二：异构硬件适配。** 不同客户端可能使用不同型号的国产芯片（华为、寒武纪、海光），甚至混合使用CPU和GPU。模型在不同硬件上的数值精度、计算速度、内存布局都不同。如何保证聚合后的模型在所有硬件上都能正常运行？

目前没有通用方案。我们的做法是在聚合前做硬件指纹检测，对数值差异超过阈值的客户端进行参数对齐。但这增加了系统复杂度。

**问题三：激励机制。** 联邦学习需要多个客户端参与才有意义。但参与联邦训练是有成本的（算力、电力、维护）。如果没有合理的激励机制，客户端没有动力参与。

区块链+代币是一种可能的方案（我们在Embodied-FL中做了贡献量化+审计链的原型），但代币的法律地位、税务处理、反洗钱合规等问题尚未解决。

---

### 我的判断

英伟达断供不是短期事件，是长期趋势。国产替代需要时间，但数据合规的约束不会放松。

在这个双重约束下，联邦学习从"隐私保护的选项"变成了"AI基础设施的必选项"。

如果你正在做AI项目，现在就开始考虑联邦学习的架构。不要等数据合规审查来了才临时抱佛脚。

### 完整代码

```python
"""Reading-FL: 联邦阅读情感模型训练Pipeline

基于FedAvg的多校区书摘情感分类联邦学习框架。
数据：3校区273条书摘，5类情感标签。
模型：文本特征提取 + 分类头。
聚合：标准FedAvg（按样本数加权）。

注意：FedAvg必须按样本数加权，不能简单平均。
公式：w_global = Σ(n_k/N) * w_k
"""

import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import Dataset, DataLoader
from typing import List, Dict, Tuple, Optional
import numpy as np
import json
import logging
from pathlib import Path
from dataclasses import dataclass, field

logger = logging.getLogger(__name__)


@dataclass
class FLConfig:
    """联邦学习训练配置"""
    num_rounds: int = 20          # 联邦轮数
    local_epochs: int = 5         # 每轮本地训练epoch数
    learning_rate: float = 1e-4   # 学习率
    batch_size: int = 16          # 批大小
    num_clients: int = 3          # 客户端数量（3个校区）
    min_clients_per_round: int = 2  # 每轮最少参与客户端
    gradient_clip: float = 1.0    # 梯度裁剪阈值
    top_k_ratio: float = 0.1      # Top-K稀疏化比例（10%）
    device: str = field(
        default_factory=lambda: "cuda" if torch.cuda.is_available() else "cpu"
    )


class BookExcerptDataset(Dataset):
    """书摘情感数据集

    每条数据：
    - text: 书摘文本
    - label: 情感标签（0-4: 启发/感动/平静/焦虑/悲伤）
    - campus: 校区标识
    """

    EMOTION_LABELS = ["启发", "感动", "平静", "焦虑", "悲伤"]

    def __init__(self, data_path: str, campus: Optional[str] = None):
        self.data_path = Path(data_path)
        if not self.data_path.exists():
            raise FileNotFoundError(f"数据文件不存在: {data_path}")

        with open(self.data_path, 'r', encoding='utf-8') as f:
            raw_data = json.load(f)

        self.samples = []
        for item in raw_data:
            if campus and item.get("campus") != campus:
                continue
            text = item.get("text", "").strip()
            label_str = item.get("emotion", "")
            if text and label_str in self.EMOTION_LABELS:
                self.samples.append({
                    "text": text,
                    "label": self.EMOTION_LABELS.index(label_str),
                    "campus": item.get("campus", "unknown")
                })

        if not self.samples:
            raise ValueError(
                f"没有有效数据。campus={campus}, "
                f"原始数据量={len(raw_data)}"
            )

        logger.info(
            f"加载数据集: {len(self.samples)}条, "
            f"campus={campus or '全部'}"
        )

    def __len__(self) -> int:
        return len(self.samples)

    def __getitem__(self, idx: int) -> Dict:
        return self.samples[idx]


class EmotionClassifier(nn.Module):
    """阅读情感分类模型

    架构：特征提取层 + 分类头
    实际项目中特征提取替换为BERT/sentence-transformers，
    这里用全连接层作为示例。
    """

    def __init__(self, input_dim: int = 768, num_classes: int = 5,
                 hidden_dim: int = 256):
        super().__init__()
        self.feature_extractor = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(hidden_dim, hidden_dim // 2),
            nn.ReLU(),
            nn.Dropout(0.2),
        )
        self.classifier = nn.Linear(hidden_dim // 2, num_classes)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        features = self.feature_extractor(x)
        return self.classifier(features)


class FLClient:
    """联邦学习客户端（模拟单个校区）"""

    def __init__(self, client_id: str, dataset: Dataset,
                 config: FLConfig):
        self.client_id = client_id
        self.dataset = dataset
        self.config = config
        self.data_size = len(dataset)

        self.model = EmotionClassifier().to(config.device)
        self.optimizer = optim.Adam(
            self.model.parameters(), lr=config.learning_rate
        )
        self.criterion = nn.CrossEntropyLoss()

    def local_train(self, global_params: Dict[str, torch.Tensor]
                    ) -> Tuple[Dict[str, torch.Tensor], float]:
        """本地训练

        Args:
            global_params: 全局模型参数

        Returns:
            (参数更新, 平均训练损失)
        """
        # 加载全局参数
        self.model.load_state_dict(global_params)
        self.model.train()

        loader = DataLoader(
            self.dataset, batch_size=self.config.batch_size,
            shuffle=True, drop_last=False
        )

        total_loss = 0.0
        num_batches = 0

        for _ in range(self.config.local_epochs):
            for batch in loader:
                features = self._extract_features(batch["text"])
                labels = batch["label"].to(self.config.device)

                self.optimizer.zero_grad()
                outputs = self.model(features)
                loss = self.criterion(outputs, labels)
                loss.backward()

                # 梯度裁剪（防止梯度爆炸）
                torch.nn.utils.clip_grad_norm_(
                    self.model.parameters(), self.config.gradient_clip
                )

                self.optimizer.step()
                total_loss += loss.item()
                num_batches += 1

        avg_loss = total_loss / max(num_batches, 1)

        # 计算参数更新（本地参数 - 全局参数）
        local_params = {
            name: param.data.clone()
            for name, param in self.model.named_parameters()
        }
        updates = {
            name: local_params[name] - global_params[name]
            for name in global_params
        }

        return updates, avg_loss

    def _extract_features(self, texts: List[str]) -> torch.Tensor:
        """文本特征提取

        实际项目中替换为：
        - sentence-transformers（推荐）
        - BERT（精度更高但更慢）
        - TF-IDF（最简单但效果一般）
        """
        batch_size = len(texts)
        dummy_features = torch.randn(
            batch_size, 768, device=self.config.device
        )
        return dummy_features

    def evaluate(self, test_dataset: Dataset) -> Dict[str, float]:
        """评估模型准确率"""
        self.model.eval()
        loader = DataLoader(
            test_dataset, batch_size=self.config.batch_size
        )

        correct = 0
        total = 0

        with torch.no_grad():
            for batch in loader:
                features = self._extract_features(batch["text"])
                labels = batch["label"].to(self.config.device)
                outputs = self.model(features)
                preds = outputs.argmax(dim=1)
                correct += (preds == labels).sum().item()
                total += labels.size(0)

        accuracy = correct / max(total, 1)
        return {"accuracy": accuracy, "total": total}


class FLSimulator:
    """联邦学习模拟器（Reading-FL）"""

    def __init__(self, config: FLConfig):
        self.config = config
        self.global_model = EmotionClassifier().to(config.device)
        self.clients: Dict[str, FLClient] = {}
        self.history: List[Dict] = []

    def register_client(self, client_id: str, dataset: Dataset):
        """注册客户端（校区）"""
        self.clients[client_id] = FLClient(
            client_id, dataset, self.config
        )
        logger.info(
            f"注册客户端 {client_id}: "
            f"{len(dataset)}条数据"
        )

    def _fedavg(self, updates: List[Tuple[Dict, int]]
                ) -> Dict[str, torch.Tensor]:
        """标准FedAvg聚合（按样本数加权）

        ⚠️ 关键：必须按样本数加权！
        公式：w_global = Σ(n_k/N) * w_k
        不能用 .mean(dim=0)，否则大客户端和小客户端
        的贡献会被错误地等同对待。

        Args:
            updates: [(参数更新, 数据量), ...]

        Returns:
            聚合后的全局参数更新
        """
        total_samples = sum(n for _, n in updates)
        if total_samples == 0:
            raise ValueError("所有客户端数据量为0")

        aggregated = {}
        for name in updates[0][0]:
            # 按样本数加权求和
            weighted_sum = sum(
                u[name] * (n / total_samples) for u, n in updates
            )
            aggregated[name] = weighted_sum

        return aggregated

    def _top_k_sparsify(self, updates: Dict[str, torch.Tensor]
                        ) -> Dict[str, torch.Tensor]:
        """Top-K稀疏化：只保留绝对值最大的K个参数

        通信量压缩约10倍，精度损失可忽略。
        """
        sparsified = {}
        for name, param in updates.items():
            flat = param.flatten()
            k = max(1, int(len(flat) * self.config.top_k_ratio))
            _, top_indices = flat.abs().topk(k)

            mask = torch.zeros_like(flat)
            mask[top_indices] = flat[top_indices]

            sparsified[name] = mask.reshape(param.shape)
        return sparsified

    def run(self) -> List[Dict]:
        """执行联邦训练"""
        global_params = {
            name: param.data.clone()
            for name, param in self.global_model.named_parameters()
        }

        for round_idx in range(self.config.num_rounds):
            round_result = {"round": round_idx + 1}

            # 随机选择客户端
            available = list(self.clients.keys())
            num_selected = max(
                self.config.min_clients_per_round,
                min(len(available), self.config.num_clients)
            )
            selected = np.random.choice(
                available, size=num_selected, replace=False
            )

            # 本地训练
            updates = []
            for cid in selected:
                client = self.clients[cid]
                try:
                    local_update, loss = client.local_train(
                        global_params
                    )
                    # Top-K稀疏化压缩通信
                    sparse_update = self._top_k_sparsify(local_update)
                    updates.append((sparse_update, client.data_size))
                    round_result[f"loss_{cid}"] = loss
                except RuntimeError as e:
                    logger.warning(
                        f"客户端 {cid} 训练失败: {e}"
                    )
                    continue

            if not updates:
                logger.error(f"第{round_idx+1}轮无有效更新")
                continue

            # FedAvg聚合（按样本数加权）
            aggregated_update = self._fedavg(updates)

            # 更新全局模型
            for name in global_params:
                global_params[name] += aggregated_update[name]

            self.global_model.load_state_dict(global_params)

            # 记录
            round_result["num_clients"] = len(updates)
            round_result["total_samples"] = sum(
                n for _, n in updates
            )
            self.history.append(round_result)

            logger.info(
                f"Round {round_idx+1}/{self.config.num_rounds}: "
                f"clients={len(updates)}, "
                f"samples={round_result['total_samples']}"
            )

        return self.history


# === 使用示例 ===
if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)

    config = FLConfig(num_rounds=20, local_epochs=5)

    simulator = FLSimulator(config)

    # 注册3个校区（实际使用时替换为真实数据路径）
    campuses = ["campus_a", "campus_b", "campus_c"]
    for campus in campuses:
        try:
            dataset = BookExcerptDataset(
                "data/book_excerpts.json", campus=campus
            )
            simulator.register_client(campus, dataset)
        except (FileNotFoundError, ValueError) as e:
            logger.warning(f"跳过 {campus}: {e}")

    # 执行联邦训练
    if len(simulator.clients) >= config.min_clients_per_round:
        history = simulator.run()
        print(f"训练完成，共{len(history)}轮")
    else:
        print("客户端数量不足，无法启动联邦训练")
```

### 踩坑记录

**坑1：FedAvg加权（血泪教训）**

最初用 `torch.mean(dim=0)` 做参数聚合，三个校区的数据量分别是120、85、68，简单平均导致大校区的贡献被稀释。

修复：按样本数加权 `w_global = Σ(n_k/N) * w_k`。修复后准确率从78.2%提升到85.5%。

**教训：FedAvg的"Avg"不是简单平均，是加权平均。权重是样本数。**

**坑2：数据不均衡导致模型偏向大类**

"启发"类占28.6%，"悲伤"类仅13.6%。模型倾向于把所有样本预测为"启发"。

解决方案：在CrossEntropyLoss中加入class weights， inversely proportional to class frequency。

```python
class_weights = torch.tensor([1/0.286, 1/0.238, 1/0.190, 1/0.150, 1/0.136])
class_weights = class_weights / class_weights.sum()
criterion = nn.CrossEntropyLoss(weight=class_weights.to(device))
```

**坑3：校区间数据分布差异（Non-IID）**

校区A偏文学类书摘，校区B偏科技类，校区C偏心理类。直接聚合导致"负迁移"——聚合后准确率反而低于单个校区。

当前方案：FedAvg + Top-K稀疏化。Top-K天然起到"特征选择"的作用，只保留每个校区最有区分度的参数，减少了异构数据的干扰。

更优方案（计划中）：用任务感知聚合（类似Embodied-FL的HNSW方案），先计算校区间的数据分布相似度，再决定聚合权重。

**坑4：内存数据库的表初始化**

这个坑是从dgy-treehole项目继承的经验。Streamlit Cloud文件系统只读，SQLite只能用内存模式。但内存数据库在进程重启后清空，`init_db()` 必须在模块加载时自动调用。

```python
# db.py 末尾
_init_db()  # 模块import时自动建表
```

### 正文

今天早上刷到一条新闻，黄仁勋在接受采访的时候说，英伟达在中国AI芯片市场的份额已经降到了0%。

评论区炸了。有人说"早该断了"，有人说"国产芯片还差得远"，有人说"这是倒退"。

我看完之后没有马上评论。我靠在椅子上，盯着天花板发了一会儿呆。

然后我想起了一件事。

---

### 1996年的那台386

我上初中的时候，学校微机室里有六台电脑。其中五台是386，一台是486。

386的内存只有4MB，硬盘40MB，没有鼠标，全靠键盘操作。开机要等两分钟，屏幕上先出现一堆英文字母，然后才慢慢跳出一个蓝色的界面。

那时候学的是BASIC语言。老师教我们用PRINT语句在屏幕上输出"HELLO WORLD"。全班同学对着黑底白字的屏幕，觉得这就是全世界最酷的事情。

486比386快很多，但只有一台。每次上机课，谁坐到486面前，全班都羡慕。

有一次我问老师，为什么我们不能都用486？

老师说，486是美国Intel公司的，一台要一万多块钱。学校买不起。

那时候一万多块钱是什么概念？我爸一个月工资三百块。一台486相当于我爸三年多的工资。

后来我才知道，386也是Intel的。只不过386是上一代产品，国内已经能仿制了。仿制的386比原装的便宜很多，但性能差一些，偶尔会死机。

我们用的就是仿制的386。

---

### 仿制和替代

三十年的时间，从仿制386到华为昇腾，中国芯片产业走了很远。

但有些东西没有变。

1996年，我们用仿制386，是因为买不起Intel的。2026年，我们用华为昇腾，是因为买不到英伟达的。

原因不同，但处境相似：**别人有的，我们没有。**

区别在于，1996年的386仿制品，性能只有原装的七八成。2026年的华为昇腾910B，单卡算力已经接近H100的八九成。差距在缩小，但还在。

黄仁勋说份额归零，说的是"直接面向中国客户的销售完全停滞"。不是英伟达不想卖，是美国政府不让卖。

这件事对AI行业的影响，比大部分人想象的要大。

---

### 为什么比想象的大

很多人以为，英伟达断供只是"算力变贵了"。用国产芯片替代，虽然贵一点、慢一点，但总能凑合。

这种想法忽略了一个关键问题：**算力不是孤立存在的，它和训练架构深度绑定。**

传统的AI训练模式是这样的：把所有数据搬到一台超级计算机上，用几千张显卡一起训练。这种模式的前提是——你有足够的算力集中在一个地方。

英伟达的芯片之所以强大，不只是因为单卡算力高，还因为它的软件生态（CUDA）让几千张卡能高效协同工作。你买一台装满H100的服务器，插上电就能跑。

国产芯片呢？单卡算力在追，但多卡协同的软件生态还差得远。你买一百张华为昇腾，想让它们像一百张H100一样协同工作，需要自己写大量的适配代码。

所以问题不只是"芯片够不够强"，而是"能不能把算力高效地组织起来"。

---

### 换一种思路

我做了几年联邦学习的研究。联邦学习的核心思路，用大白话说就是：**不把数据搬到算力那里，而是让算力去数据那里。**

每个有数据的地方（医院、学校、企业）用自己的设备做本地训练，训练完只把"学到了什么"传回服务器。服务器把所有地方的经验汇总起来，形成一个更好的模型，再分发回去。

原始数据永远不离开本地。

这个思路在英伟达断供之前，主要是为了解决隐私问题。但现在，它意外地解决了另一个问题：**算力分散。**

你不需要一台装满H100的超级计算机。你只需要每个地方有一台"够用"的计算机。一百个地方，每个地方用一张国产芯片，加起来的训练效果可能比一台超级计算机还好。

而且，数据不出本地，天然满足数据安全法的要求。

这不是理论。我们实验室做了一个叫Reading-FL的项目，三个校区，两百多条书摘，数据全部留在各校区，联邦训练后准确率85.5%。用的就是普通的显卡，不是什么超级计算机。

---

### 我妈和电脑

说到这里，我想起我妈。

我妈是中学老师，教数学。她这辈子跟电脑打交道只有两件事：一是用Word打教案，二是用微信跟学生家长聊天。

去年有一次我回家，她问我："你们搞的那个什么AI，是不是就是ChatGPT？"

我说差不多。

她说："那它能不能帮我改改学生的作业？我每天改作业改到晚上十一点。"

我说可以啊，我给你装一个。

然后我花了半个小时帮她装了一个AI批改工具。她试了一下，特别高兴，说这个太好了，以后每天能省一个小时。

第二天她又问我："但是这个工具会不会把学生的作业传到网上去？家长会不会有意见？"

我当时愣了一下。

一个中学数学老师，从来没学过计算机，从来没听说过"数据隐私"这个词，但她直觉地想到了这个问题。

我说不会，这个工具是在你电脑上运行的，数据不会传出去。

她这才放心。

---

### 母亲节

这周六是母亲节。

我妈不知道什么是英伟达，不知道什么是联邦学习，不知道什么是OPC。她只知道她儿子在大学里"搞电脑"。

但她知道两件事：第一，学生的作业不能随便传到网上。第二，她儿子做的东西应该是有用的。

我觉得这两件事比任何技术指标都重要。

技术再先进，如果普通人的隐私得不到保护，那就是空中楼阁。算力再强大，如果不能让像我妈这样的普通人用得上、用得放心，那就是浪费。

英伟达走了。国产芯片在追赶。联邦学习在发展。OPC在成长。

但最终，所有这些技术的终点，应该是让每一个人——包括我妈这样的中学老师——能够安全地、方便地、有尊严地使用AI。

母亲节快到了。如果你还在纠结送什么，推荐一本书：《代码乡愁》。讲一个老程序员和AI的故事。QQ阅读免费。

我妈看完之后说了一句："你写的这个老陈，有点像你爸。"

我没问她为什么。有些答案，不需要说出来。

提前祝所有妈妈母亲节快乐。
