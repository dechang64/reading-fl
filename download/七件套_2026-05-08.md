## 一、公众号 | SOHOForce OPC AI开放创造实验室

### 标题
**深夜灯下，有人也在同一段话停了下来——坐忘的社交哲学**

### 发布时间
**2026-05-08 20:00**（公众号晚间深度阅读高峰 19:30-21:00）

### 正文

微信读书有一个功能叫"想法"。你在读书的时候可以随时划线、写批注，其他读者能看到。

这个功能上线的时候，很多人说"太好了，终于可以和书友交流了"。但几年过去了，一个有趣的现象出现了：**大部分活跃的"想法"，都是孤独的。**

什么意思？就是你写了一条批注，可能过了几个月都没有人回应。偶尔有人点赞，但点赞的人你也不认识。你不知道他们是谁、在哪个城市、为什么也在读这本书。

更让人焦虑的是排行榜。微信读书每周会公布"阅读时长排行榜"，你的朋友能看到你读了多久。这个功能本意是激励阅读，但实际效果是：很多人为了"不输"而刷时长，阅读变成了一场社交表演。

---

### 社交的悖论

阅读本质上是一件孤独的事。

你翻开一本书，进入一个只有你和作者的世界。这个过程需要专注、需要沉浸、需要暂时切断与外界的联系。任何外部干扰——消息通知、排行榜压力、社交期待——都会破坏这种沉浸感。

但阅读又有一种天然的社交渴望。你读到一段特别好的话，想分享给某人。你读完一本书，想找人讨论。你在深夜读到一句让你流泪的话，想知道是不是只有你一个人被打动。

这就是阅读社交的悖论：**你想要连接，但不想被打扰。**

微信读书的"想法"和"排行榜"试图解决这个问题，但它们走的是"主动社交"路线——你需要主动发批注、主动看排行榜、主动参与讨论。这和阅读的"沉浸"本质是矛盾的。

---

### 坐忘的答案：安静的社交

我们正在做一款叫"坐忘"的产品。核心定位不是"微信读书让你读得更多"，而是"坐忘灯让你读得更深"。

"深"和"多"的区别是什么？

"多"是数量——你一年读了多少本书、多少小时。"深"是质量——你在一本书里停留了多久、在哪些段落停了下来、这些段落为什么打动了你。

坐忘的社交设计基于一个核心假设：**最好的阅读社交，不是"主动连接"，而是"被动发现"。**

具体来说，有三个机制：

**① 灯微闪**

想象你在深夜读书。你的坐忘灯亮着，书放在灯下。你读到一段话，停了下来，反复读了两遍。

此时，你的灯微微闪了一下。

这个"闪"不是通知，不是消息，不是提醒。它只是一个信号——告诉你，在某个你看不到的地方，有另一个人也在读这本书，也在这一段停了下来。

你不需要回应。你不需要知道那个人是谁。你只需要知道：你不是一个人。

这就是"灯微闪"——最低干扰的社交信号。

**② 一杯咖啡的距离**

如果你对那个"灯微闪"的人好奇，你可以选择"靠近"——就像在咖啡馆里，你注意到对面桌的人也在读同一本书，你犹豫了一下，然后端着咖啡走过去说"你也在读这本？"

但"靠近"是单向的。对方不会立刻知道你是谁。只有当对方也选择"靠近"你时，你们才会看到彼此的身份。

这叫"一杯咖啡的距离"——**双向同意，才暴露身份。**

**③ 书摘漂流瓶**

你可以在坐忘里"放漂"一段书摘——匿名，不署名，不暴露身份。其他读者在随机浏览时可能捡到你的书摘。如果被打动，可以"回应"——同样匿名。

这是一种异步的、完全匿名的轻社交。没有社交压力，没有"已读不回"的尴尬，没有"要不要点赞"的纠结。

---

### 为什么需要联邦学习？

上面说的三个机制，技术上有一个核心挑战：**如何知道"有人在同一段话停了下来"，同时不暴露这个人的身份和阅读数据？**

传统方案是集中式——把所有人的阅读数据上传到服务器，服务器做匹配。但这违反了坐忘的基本原则：**阅读数据是个人隐私，不应该离开你的设备。**

联邦学习提供了一种优雅的解决方案：

1. 每个用户的坐忘灯在本地记录阅读行为（在哪些段落停留、停留了多久）
2. 本地模型将这些行为编码为"阅读特征向量"（不包含原文内容）
3. 只传输"阅读特征向量"到服务器，服务器用近似最近邻算法（HNSW）找到相似的用户
4. 匹配成功后，只通知"有人也在这一段停了下来"，不暴露任何个人信息

**原始阅读数据永远不离开你的设备。** 服务器只知道"有人在这一段停了下来"，不知道"谁"停了下来、"为什么"停下来。

这不是理论。我们实验室的Reading-FL项目已经验证了这条路径——三个校区，273条书摘，数据全部留在各校区本地，用联邦学习聚合，准确率85.5%。

---

### 从产品到社会实验

坐忘不只是一个阅读产品，它是一个社会实验。

我们想验证一个假设：**在AI时代，"安静的社交"可能比"热闹的社交"更有价值。**

过去十年，社交媒体的逻辑是"越热闹越好"——更多的点赞、更多的评论、更多的转发、更多的粉丝。这个逻辑催生了短视频、直播、热搜、饭圈。但也催生了焦虑、抑郁、信息茧房、网络暴力。

OPC（Open Platform Creator）的崛起，暗示了一种不同的可能性：一个人+AI工具链=一个团队。这意味着一个人可以独立完成以前需要团队才能完成的事——写文章、做视频、做产品、做研究。

但当一个人可以独立完成所有事的时候，他还需要社交吗？

我的答案是：需要，但需要的是不同类型的社交。

不是"看我多厉害"的表演型社交，而是"原来你也在"的陪伴型社交。不是"给我点赞"的索取型社交，而是"这段话也打动了你"的共鸣型社交。

坐忘想做的，就是这种社交。

## 三、知乎 | 小蠹OPC

### 标题
**为什么阅读社交产品都在做"排行榜"，但没有人真正喜欢？**

### 发布时间
**2026-05-08 21:00**（知乎晚间技术阅读高峰 20:00-22:00）

### 正文

微信读书的"阅读时长排行榜"上线时，产品经理的预期是：通过社交压力激励用户多读书。

几年过去了，结果如何？

根据我观察到的现象（非官方数据）：排行榜确实提升了部分用户的阅读时长，但也催生了大量"刷时长"行为——打开书不读、挂着后台充时长、甚至用脚本自动翻页。更严重的是，排行榜让阅读变成了一场"社交表演"，很多人因为"读得不如朋友多"而感到焦虑，最终卸载了App。

这不是微信读书独有的问题。豆瓣的"读过"标记、Goodreads的"年度阅读挑战"、掌阅的"阅读成就"——几乎所有阅读社交产品都在做"主动社交"，但用户的真实反馈往往是"累"。

为什么？

---

### 阅读社交的根本矛盾

阅读有两个看似矛盾的属性：

**第一，阅读是内向的。** 它需要专注、沉浸、与外界隔离。任何外部干扰都会破坏阅读体验。

**第二，阅读有社交需求。** 读者想分享、想讨论、想知道"是不是只有我被这段话打动了"。

传统社交产品（微信、微博、抖音）的逻辑是"主动连接"——你发内容，别人看到，互动。这个逻辑在信息消费场景（刷短视频、看新闻）下很有效，但在阅读场景下会产生矛盾：

- 你在深度阅读时，不想被打断（内向需求）
- 但产品希望你发"想法"、看排行榜、参与讨论（主动社交需求）

这两个需求在时间上是冲突的。你在读书的时候不想看排行榜，看完书之后又想找人讨论。但产品把这两个功能放在同一个界面里，结果就是：阅读体验被社交功能破坏了。

---

### "安静的社交"：一种不同的设计哲学

我们正在做的"坐忘"产品，尝试了一种不同的路径。核心假设是：

**阅读社交不应该是"主动连接"，而应该是"被动发现"。**

具体来说，我们设计了三种社交机制：

**机制一：灯微闪（被动感知）**

用户在阅读时，如果在一个段落停留时间超过阈值（比如反复读了2遍），系统会检测是否有其他用户也在同一本书的同一区域停留过。如果有，用户的阅读灯会"微闪"一下。

这不是通知，不需要回应。只是一个信号："你不是一个人。"

设计要点：
- 不显示对方身份（隐私保护）
- 不需要用户主动操作（零干扰）
- 信号强度与"共鸣程度"正相关（停留时间越长，闪得越明显）

**机制二：一杯咖啡的距离（双向同意）**

如果用户对"灯微闪"产生好奇，可以选择"靠近"。但"靠近"是单向的——对方不会立刻知道。只有当双方都选择"靠近"时，才会暴露身份。

这类似于咖啡馆里的自然社交：你注意到对面桌的人也在读同一本书，你犹豫了一下，然后走过去搭话。但对方也有选择不回应的权利。

**机制三：书摘漂流瓶（异步匿名）**

用户可以匿名"放漂"一段书摘。其他用户随机"捡到"后，可以匿名回应。完全异步，完全匿名，零社交压力。

---

### 技术实现：联邦学习+HNSW

"灯微闪"的核心技术挑战是：**如何在不知道"谁在读什么"的前提下，匹配"在同一本书的同一区域停留"的用户？**

传统方案是集中式匹配——把所有用户的阅读行为上传到服务器。但这违反了阅读隐私原则。

我们的方案基于联邦学习：

1. **本地特征提取**：每个用户的设备在本地将阅读行为（停留位置、停留时长、反复阅读次数）编码为"阅读特征向量"。特征向量不包含原文内容，无法反推出用户读了什么。

2. **联邦传输**：只传输"阅读特征向量"到服务器，原始阅读数据不离开设备。

3. **HNSW匹配**：服务器用HNSW（Hierarchical Navigable Small World）算法进行近似最近邻搜索，找到阅读特征相似的用户。

4. **隐私通知**：匹配成功后，只通知"有人也在这一段停了下来"，不暴露任何个人信息。

HNSW的选择理由：
- 高效：百万级用户的实时匹配，延迟<100ms
- 可扩展：新增用户不需要重建索引
- 已验证：我们在Embodied-FL项目中用HNSW做任务相似度匹配，效果良好

---

### 为什么"安静的社交"可能是未来

过去十年的社交媒体，走的是"热闹"路线——更多的互动、更多的连接、更多的数据。这个路线在信息消费场景下取得了巨大成功（抖音、快手、小红书），但在深度内容场景下（阅读、学习、思考）遇到了瓶颈。

原因很简单：**深度内容需要安静，而"热闹"的社交设计天然破坏安静。**

OPC（Open Platform Creator）的崛起暗示了一种趋势：一个人+AI工具链=一个团队。当一个人可以独立完成内容创作时，他对"热闹社交"的需求会降低，但对"深度共鸣"的需求会升高。

"安静的社交"不是反社交，是另一种社交。它承认人的社交需求，但不让社交需求破坏人的独处需求。

---

### 三个待解决的问题

说了这么多理想，也要坦诚面对问题。

**问题一：冷启动。** "灯微闪"需要足够多的用户才能产生有意义的匹配。在用户量较少的早期，匹配成功率会很低，用户体验会打折扣。

### 核心功能：HNSW相似基金推荐

MVP的核心交互：输入基金代码 → 返回风险画像 + 最相似的5只基金。

相似度计算基于HNSW（Hierarchical Navigable Small World）算法。为什么选HNSW而不是暴力搜索或KD-Tree？

- **暴力搜索**：O(n)复杂度，63只基金可以接受，但扩展到1000+只时不可行
- **KD-Tree**：适合低维数据（<20维），基金风险指标有15+维，效果差
- **HNSW**：对高维数据友好，查询时间复杂度接近O(log n)，支持增量插入

代码复用：hnsw_index.rs直接从Embodied-FL项目复制，代码复用率约60%。

```rust
// hnsw_index.rs - HNSW相似度搜索核心

use std::collections::{HashMap, HashSet};

#[derive(Debug, Clone)]
pub struct HNSWIndex {
    /// 最大层高
    max_level: usize,
    /// 每层最大连接数
    m: usize,
    /// 搜索时的候选宽度
    ef_search: usize,
    /// 节点集合
    nodes: HashMap<String, HNSWNode>,
    /// 入口节点
    entry_point: Option<String>,
}

#[derive(Debug, Clone)]
pub struct HNSWNode {
    pub id: String,
    pub vector: Vec<f64>,
    pub neighbors: Vec<Vec<String>>,  // neighbors[level] = [neighbor_ids]
    pub level: usize,
}

impl HNSWIndex {
    pub fn new(m: usize, ef_construction: usize, ef_search: usize) -> Self {
        Self {
            max_level: 0,
            m,
            ef_search,
            nodes: HashMap::new(),
            entry_point: None,
        }
    }

    /// 插入一个新节点
    pub fn insert(&mut self, id: String, vector: Vec<f64>) {
        let level = self._random_level();
        let node = HNSWNode {
            id: id.clone(),
            vector,
            neighbors: vec![Vec::new(); level + 1],
            level,
        };

        if self.entry_point.is_none() {
            self.entry_point = Some(id.clone());
            self.max_level = level;
            self.nodes.insert(id, node);
            return;
        }

        // 从入口节点开始，逐层搜索最近邻
        let entry = self.entry_point.clone().unwrap();
        let mut current = entry;

        // 从顶层向下搜索
        for l in (level + 1..=self.max_level).rev() {
            current = self._search_layer(current, &node.vector, l, 1);
        }

        // 在0到level层搜索并连接
        for l in (0..=level).rev() {
            let candidates = self._search_layer(
                current, &node.vector, l, self.ef_search
            );
            for cand_id in candidates.iter().take(self.m) {
                node.neighbors[l].push(cand_id.clone());
                if let Some(neighbor) = self.nodes.get_mut(cand_id) {
                    if neighbor.neighbors.len() > l {
                        neighbor.neighbors[l].push(id.clone());
                    }
                }
            }
        }

        if level > self.max_level {
            self.max_level = level;
            self.entry_point = Some(id);
        }

        self.nodes.insert(id, node);
    }

    /// 搜索最近的k个邻居
    pub fn search(&self, query: &[f64], k: usize) -> Vec<(String, f64)> {
        let entry = match &self.entry_point {
            Some(e) => e.clone(),
            None => return vec![],
        };

        let mut current = entry;

        for l in (1..=self.max_level).rev() {
            current = self._search_layer(current, query, l, 1);
        }

        let candidates = self._search_layer(current, query, 0, self.ef_search);

        candidates.iter().take(k).map(|id| {
            let node = self.nodes.get(id).unwrap();
            let dist = Self::cosine_similarity(query, &node.vector);
            (id.clone(), dist)
        }).collect()
    }

    fn _search_layer(&self, entry: &str, query: &[f64],
                     level: usize, ef: usize) -> Vec<String> {
        let mut visited = HashSet::new();
        visited.insert(entry.to_string());
        let mut candidates = vec![entry.to_string()];

        for _ in 0..ef {
            let mut best_dist = f64::NEG_INFINITY;
            let mut best_id = String::new();

            for cand_id in &candidates {
                if let Some(node) = self.nodes.get(cand_id) {
                    let dist = Self::cosine_similarity(query, &node.vector);
                    if dist > best_dist {
                        best_dist = dist;
                        best_id = cand_id.clone();
                    }
                }
            }

            if let Some(node) = self.nodes.get(&best_id) {
                if node.neighbors.len() > level {
                    for neighbor_id in &node.neighbors[level] {
                        if !visited.contains(neighbor_id) {
                            visited.insert(neighbor_id.clone());
                            candidates.push(neighbor_id.clone());
                        }
                    }
                }
            }
        }

        let mut scored: Vec<(String, f64)> = candidates.iter().map(|id| {
            let node = self.nodes.get(id).unwrap();
            let dist = Self::cosine_similarity(query, &node.vector);
            (id.clone(), dist)
        }).collect();

        scored.sort_by(|a, b| b.1.partial_cmp(&a.1).unwrap());
        scored.into_iter().map(|(id, _)| id).collect()
    }

    fn cosine_similarity(a: &[f64], b: &[f64]) -> f64 {
        let dot: f64 = a.iter().zip(b).map(|(x, y)| x * y).sum();
        let norm_a: f64 = a.iter().map(|x| x * x).sum::<f64>().sqrt();
        let norm_b: f64 = b.iter().map(|x| x * x).sum::<f64>().sqrt();
        if norm_a < 1e-8 || norm_b < 1e-8 {
            return 0.0;
        }
        dot / (norm_a * norm_b)
    }

    fn _random_level(&self) -> usize {
        // 简化版：固定返回2
        2
    }
}
```

```python
"""FundFL: 基金风险分析Pipeline

输入：基金代码
输出：风险画像 + 最相似的5只基金
"""

import json
import numpy as np
from pathlib import Path
from dataclasses import dataclass
from typing import List, Dict, Optional


@dataclass
class FundProfile:
    """基金风险画像"""
    code: str
    name: str
    asset_class: str
    monthly_returns: np.ndarray
    volatility: float
    sharpe_ratio: float
    max_drawdown: float
    beta: float
    alpha: float
    information_ratio: float
    tracking_error: float


class FundAnalyzer:
    """基金风险分析器"""

    def __init__(self, data_path: str):
        self.data_path = Path(data_path)
        self.funds: Dict[str, FundProfile] = {}
        self._load_data()

    def _load_data(self):
        with open(self.data_path, 'r') as f:
            raw = json.load(f)

        for item in raw:
            returns = np.array(item['monthly_returns'])
            profile = FundProfile(
                code=item['code'],
                name=item['name'],
                asset_class=item['asset_class'],
                monthly_returns=returns,
                volatility=float(np.std(returns) * np.sqrt(12)),
                sharpe_ratio=self._calc_sharpe(returns),
                max_drawdown=self._calc_max_drawdown(returns),
                beta=item.get('beta', 0.0),
                alpha=item.get('alpha', 0.0),
                information_ratio=item.get('ir', 0.0),
                tracking_error=item.get('te', 0.0),
            )
            self.funds[item['code']] = profile

    def _calc_sharpe(self, returns: np.ndarray,
                     risk_free_rate: float = 0.02) -> float:
        """计算年化夏普比率"""
        excess = returns - risk_free_rate / 12
        if np.std(excess) < 1e-8:
            return 0.0
        return float(np.mean(excess) / np.std(excess) * np.sqrt(12))

    def _calc_max_drawdown(self, returns: np.ndarray) -> float:
        """计算最大回撤"""
        cumulative = np.cumprod(1 + returns)
        peak = np.maximum.accumulate(cumulative)
        drawdown = (cumulative - peak) / peak
        return float(np.min(drawdown))

    def get_risk_vector(self, code: str) -> Optional[np.ndarray]:
        """获取基金的风险特征向量（用于HNSW搜索）"""
        fund = self.funds.get(code)
        if not fund:
            return None

        return np.array([
            fund.volatility,
            fund.sharpe_ratio,
            fund.max_drawdown,
            fund.beta,
            fund.alpha,
            fund.information_ratio,
            fund.tracking_error,
            # 加入收益率分布特征
            float(np.mean(fund.monthly_returns)),
            float(np.median(fund.monthly_returns)),
            float(np.skew(fund.monthly_returns)),
            float(np.kurtosis(fund.monthly_returns)),
            # 加入尾部风险
            float(np.percentile(fund.monthly_returns, 5)),
            float(np.percentile(fund.monthly_returns, 95)),
        ])

    def find_similar(self, code: str, k: int = 5
                     ) -> List[Dict]:
        """找到最相似的k只基金"""
        query_vector = self.get_risk_vector(code)
        if query_vector is None:
            return []

        similarities = []
        for other_code, other_fund in self.funds.items():
            if other_code == code:
                continue
            other_vector = self.get_risk_vector(other_code)
            if other_vector is None:
                continue

            # 余弦相似度
            dot = np.dot(query_vector, other_vector)
            norm = np.linalg.norm(query_vector) * np.linalg.norm(other_vector)
            if norm < 1e-8:
                sim = 0.0
            else:
                sim = float(dot / norm)

            similarities.append({
                'code': other_code,
                'name': other_fund.name,
                'asset_class': other_fund.asset_class,
                'similarity': round(sim, 4),
                'volatility': round(other_fund.volatility, 4),
                'sharpe_ratio': round(other_fund.sharpe_ratio, 4),
                'max_drawdown': round(other_fund.max_drawdown, 4),
            })

        similarities.sort(key=lambda x: x['similarity'], reverse=True)
        return similarities[:k]

    def get_full_profile(self, code: str) -> Optional[Dict]:
        """获取基金的完整风险画像"""
        fund = self.funds.get(code)
        if not fund:
            return None

        similar = self.find_similar(code, k=5)

        return {
            'code': fund.code,
            'name': fund.name,
            'asset_class': fund.asset_class,
            'risk_metrics': {
                'volatility': round(fund.volatility, 4),
                'sharpe_ratio': round(fund.sharpe_ratio, 4),
                'max_drawdown': round(fund.max_drawdown, 4),
                'beta': round(fund.beta, 4),
                'alpha': round(fund.alpha, 4),
                'information_ratio': round(fund.information_ratio, 4),
                'tracking_error': round(fund.tracking_error, 4),
            },
            'similar_funds': similar,
        }


# === 使用示例 ===
```

### 踩坑记录

**坑1：HNSW的随机层级生成**

简化版用固定层级（返回2），实际应该用指数分布。否则所有节点的层级相同，HNSW退化为普通图搜索，查询效率从O(log n)退化到O(n)。

```rust
fn _random_level(&self) -> usize {
    let mut level = 0;
    let mut rng = rand::thread_rng();
    while rng.gen::<f64>() < 0.5 && level < self.max_level {
        level += 1;
    }
    level
}
```

**坑2：余弦相似度的数值稳定性**

基金风险指标中，某些值可能为0（如货币基金的Beta接近0）。必须加零向量保护，否则除以0导致NaN。

**坑3：月度收益率的异常值**

部分基金在特定月份可能有极端收益（如分红、拆分），导致风险指标失真。需要在加载数据时做异常值检测和处理（winsorize到1%-99%分位）。

### 联邦学习路线图

当前MVP是单机版。v1.0的目标是支持多机构联邦协作：

1. 每个机构（私募、券商、学术团队）在本地运行FundAnalyzer
2. 本地训练风险预测模型（如LSTM预测下月收益率）
3. 只传输模型参数更新（不传输原始基金数据）
4. 服务器聚合各机构的模型，形成更准确的全局风险模型

**为什么金融领域需要联邦学习？**

- 基金持仓数据是商业机密，不能跨机构共享
- 监管要求（证监会、银保监会）对数据出境和共享有严格限制
- 不同机构的基金组合差异大（Non-IID），联邦学习可以保留各机构的个性化

## 六、今日头条 | 小蠹OPC

### 标题
**我在苏州开了一家不卖书也不借书的书房，来的人比我想象的多**

### 发布时间
**2026-05-08 18:30**（头条晚间长文阅读高峰 18:00-20:00）
**⚠️ 注意**：不使用首发标签，内容与其他平台差异化60%+，第一人称故事驱动，口语化，~3500字，无代码块，无表格

### 正文

去年秋天，许永亮给我打了一个电话。

许永亮是做空间设计的，在苏州做了十几年。他设计过咖啡馆、民宿、展厅，但从来没设计过书房。那天他在电话里说了一句话，让我想了很久。

他说："现在的书店都在卖咖啡，咖啡馆都在卖书，但没有人做一个'什么都不卖，只让你安静待着'的地方。"

我说，那叫什么？

他说，叫坐忘。

---

### 坐忘是什么

"坐忘"这个词出自《庄子·大宗师》："堕肢体，黜聪明，离形去知，同于大通，此谓坐忘。"

翻译成大白话就是：忘掉身体的束缚，忘掉聪明才智的执念，忘掉自己的存在，和天地万物融为一体。

听起来很玄，但其实说的就是一件事：**全神贯注地沉浸在某件事里，忘记了自己。**

读书的时候，你有没有过这种体验？你翻开一本书，读着读着，周围的声音消失了，时间变快了，你完全进入了书里的世界。等你回过神来，发现已经过了两个小时。

这就是"坐忘"。

许永亮想做的，就是一个让人能"坐忘"的空间。

---

### 斜塘的那间房

坐忘书房在苏州斜塘老街旁边的一条巷子里。

不是临街的铺面，是巷子深处的一栋两层小楼。门口没有招牌，只有一盏暖色的灯。如果你不仔细看，会以为是一户普通人家。

推门进去，一楼是开放阅读区。原木色的书架从地面一直延伸到天花板，书架上放的不是畅销书排行榜上的书，而是许永亮一本一本挑出来的——有文学、有哲学、有历史、有科学，还有一些你从来没听说过的冷门好书。

每个座位旁边都有一盏独立的阅读灯。灯的亮度可以调节，色温也可以调。许永亮说，每个人对光的感觉不一样，有人喜欢暖光，有人喜欢冷光，让用户自己选。

二楼有一个小房间，门上写着"深度阅读室"。里面只有四张桌子，每张桌子之间用书架隔开。进去之后，手机信号会被屏蔽——不是强制关机，是信号被屏蔽了，你收不到消息也发不出去。

许永亮说，这个设计被很多人骂过。"你凭什么屏蔽我的手机信号？"他说，你可以不进来。

---

### 来的人

坐忘书房开张之后，我以为来的人不会太多。毕竟它不在商业区，没有招牌，不卖书不卖咖啡不卖任何东西。

但第一个月，平均每天有二十多个人来。

让我意外的是，来的人不只是年轻人。有很多中年人，甚至有老年人。

有一个六十多岁的阿姨，每周二和周四下午都会来。她每次来都带一本自己的书，坐在靠窗的位置，看两个小时，然后走。从来不跟任何人说话。

有一次我忍不住问她，您为什么来这里看书？在家看不也一样吗？

她说，不一样。在家看书，老伴会叫我吃饭，孙子会来找我玩，电话会响。在这里，没有人打扰我。两个小时，完全是我自己的。

还有一个年轻妈妈，周末会带着七八岁的女儿来。妈妈在一边看书，女儿在儿童区看绘本。两个人各看各的，偶尔女儿会跑过来给妈妈看一幅画，妈妈笑一下，然后女儿又跑回去。

没有"高质量陪伴"的焦虑，没有"你今天看了多少页"的压力。就是安静地待在一起。

---

### 灯的故事

坐忘书房里最特别的东西，是那些阅读灯。

这些灯不是普通的台灯。它们是"智能灯"——和我们的"坐忘"产品连接的。

简单说，当你在灯下读书的时候，灯会记录你的阅读行为：你在哪一页停留了多久、你反复看了哪一段、你什么时候翻页、你什么时候停下来发呆。

这些数据不会上传到任何服务器。它们只存在灯的本地存储里。

但灯会做一件事：当你在一个段落停留时间超过某个阈值（比如反复读了三遍），灯会微微闪一下。

这个"闪"不是通知，不是提醒，不是"有人给你发了消息"。它只是一个信号——告诉你，在这个空间里，或者在其他城市的某个坐忘书房里，有另一个人也在读同一本书，也在这一段停了下来。

你不需要回应。你不需要知道那个人是谁。你只需要知道：你不是一个人。

这个功能上线之后，发生了一件让我很感动的事。

有一个大学生，每周五晚上都会来坐忘书房。他总是坐在角落的位置，看一本很厚的英文书。有一次，他的灯闪了。他抬起头，看了一眼灯，然后继续看书。

后来他在我们的反馈本上写了一段话："今天灯闪了。我不知道是谁，但那一刻我觉得，深夜读书这件事，不那么孤独了。"

---

### 为什么做这个

有人问我，你们做这个有什么商业价值？

说实话，我不知道。

坐忘书房不收门票，不卖书，不卖咖啡（虽然有一台咖啡机，但免费提供）。唯一的"收入"是偶尔举办的读书会和沙龙，收一点场地费。

从商业角度看，这是一个"不赚钱"的项目。

但我们为什么做它？

因为我们在做一个更大的产品——"坐忘"。坐忘书房是这个产品的物理空间，坐忘灯是硬件载体，坐忘·读是社区空间，坐忘·见是作者工作台，坐忘·创坐会是AI替身内容工厂。

五端产品，围绕一个核心理念：**安静的社交。**

为什么是"安静"的？因为过去十年的社交媒体太吵了。排行榜、打卡、热搜、饭圈——所有的设计都在制造焦虑和噪音。我们需要一个"反方向"的产品。

---

### 母亲节

这周日是母亲节。

如果你在苏州，或者周末能来苏州，带妈妈去坐忘书房坐坐吧。

不需要做什么特别的事。就是安静地坐在一起，各看各的书。

我推荐一本书——《代码乡愁》。讲一个老程序员和AI的故事。QQ阅读免费。如果你妈妈喜欢看小说，这本不会踩雷。

但更重要的是：放下手机。

陪伴不是"我在你旁边刷手机"，是"我在你旁边，和你一起安静"。

---

### 最后

许永亮那天在电话里还说了另一句话。

他说："你知道为什么叫'坐忘'吗？因为现代人什么都'坐不住'，什么都'忘不了'。坐下来，忘掉——这本身就是一种奢侈。"

我觉得他说得对。

在这个什么都追求效率、什么都追求流量的时代，能坐下来安静地读一本书，然后忘掉时间——这确实是一种奢侈。

但奢侈的东西，往往才是最珍贵的。

后天母亲节。祝所有妈妈节日快乐。
